Settlements and open exceptions

I joined simulated trade, order and leg records in MySQL, reconciled the cash flows and fees, and independently reproduced the SQL close-month totals in Python using the same pilot trade export. For the settlement audit, I compared cumulative cash and reported profit and loss on dates with zero open trades.

The audit identified seven differences on those dates. On one date, reported cumulative profit and loss changed with zero recorded transactions. I traced each difference to its source row and recorded it as an open exception.

Three-page Power BI report

The report compares historical returns and drawdown under different funding assumptions, then tests sensitivity to fill costs, days in trade and short-put delta.

Each report comparison uses the Friday entry dates shared by the configurations it tests. The simulation uses tastytrade backtest fills, fees and daily marks. The QQQ benchmark uses Yahoo Finance dividend-adjusted closes.

The wider balance budgets increased simulated spread returns and drawdown in the midpoint scenarios. The fill-cost table shows how quickly the comparison changes as execution costs rise. Fill capacity at the largest simulated contract sizes remains unverified.
