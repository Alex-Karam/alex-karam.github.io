Method and validation

Build transaction history in MySQL

Identify each sender by bank and account ID. Count outgoing transactions recorded in the 24 hours before the current timestamp. Transactions recorded in the same minute share the same cutoff.

Train and validate by date

Use 2–6 September for training and 7–8 September for validation. The first ranking uses the paid-amount percentile within currency. The second gives that percentile 75% weight and the sender-history percentile 25%. The tree learns from both percentiles, which use the training window as their reference.

Freeze the rankings before testing

Save the fitted rankings, daily budget and tie rule before accessing the 9–10 September test labels. Rank by score each day, then break ties by timestamp and source row ID.

Reconcile the results

Check that the test IDs are unique and separate from development. For every ranking, catches plus misses reconcile to 956, and catches plus false positives reconcile to 1,000. Power BI totals match the notebook for both test days.

Limitations and sources

The results apply to two held-out days from one synthetic release at one review capacity. History covers the sender’s outgoing activity over a 24-hour window. The gain belongs to the full trained tree ranking. The independent contribution of history within the tree remains unmeasured.

IBM Research published the synthetic data through Erik Altman’s Kaggle listing, which records the Community Data License Agreement, Sharing, Version 1.0. The file used here is HI-Small_Trans.csv from version 8. Dataset and attribution · Version 8 CSV

Erik Altman, Jovan Blanuša, Luc von Niederhäusern, Béni Egressy, Andreea Anghel and Kubilay Atasu describe the generator in Realistic Synthetic Financial Transactions for Anti-Money Laundering Models. Read the paper
